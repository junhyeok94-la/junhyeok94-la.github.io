# Pop Talk DB 백업 기반 예시

## 사용 자료와 시점

- 제공된 2026-08-14 TAR는 PostgreSQL 16 물리 백업이다. 파일 목록과 PG_VERSION을 확인했으며, 물리 백업 복원이나 서버 기동은 수행하지 않았다.
- 같은 작업 폴더의 2026-08-17 논리 백업을 발견해 `pg_restore`로 로컬 SQL 파일만 생성했다. DB 접속이나 SQL 실행 없이 COPY 데이터를 읽었다.
- 공개 예시의 기준일은 **2026.08.17**이다. 8월 14일 발표 화면이나 TAR의 데이터를 복원한 화면으로 표기하지 않는다.

## 예시 1: 추천 응답과 영화 근거

- 개인정보가 없는 ‘인터스텔라와 비슷한 영화를 추천해줘’ 질문과 이어지는 저장 응답을 선택.
- 응답의 `sources`에서 `movie_recommendation`으로 연결된 영화 키를 영화 레코드와 대조.
- 인천스텔라, 인투 더 미러, 에일리언 2020이 실제 응답에 등장하고 관련 영화 레코드가 존재함을 확인.
- 이미지에는 응답의 작품명과 해당 영화의 제작 연도·상영시간·장르만 표시. 응답 전체의 사실 정확도나 추천 품질을 검증한 사례로 확대 해석하지 않음.
- 해당 요청에 벡터 검색이 실행됐는지는 이 저장 데이터만으로 확정하지 않는다.

## 예시 2: 평점 응답과 리뷰 집계

- ‘헤레틱 네이버 관람객 평점 알려줘’ 질문의 저장 응답은 3.8/5점, 299건이며 실시간 플랫폼 수치와 수집 데이터를 구분한다.
- 같은 영화, `source_system=naver_movie`, `status=ACTIVE`, `deleted_at IS NULL` 조건으로 백업 리뷰를 별도 집계.
- 리뷰 299건, 평균 약 3.8161점으로, 소수점 한 자리 반올림한 3.8점과 저장 응답이 일치함을 확인.
- 응답에 `movie`, `rating_stats` 유형의 근거가 연결돼 있음도 확인.
- 이것은 저장 응답과 해당 백업 데이터의 일치 확인이며 현재 외부 플랫폼의 평점 확인은 아니다.

## 검색 설명 정정

백업 임베딩 레코드는 `document_type=PROFILE`, `embedding_model=bge-m3`로 저장돼 있다. 보관 중인 챗봇 저장소 코드에서도 PROFILE 검색과 리뷰 SQL 조회를 확인했다. 기존 페이지의 ‘영화·리뷰 임베딩’ 표현을 **영화 프로필 벡터 검색 + 리뷰 별도 SQL 조회**로 수정했다.

## 공개 이미지의 성격

두 이미지는 선택·대조한 저장 데이터를 포트폴리오용으로 재구성한 자료다. 원본 서비스 UI를 실행해 찍은 캡처가 아니다. 이미지 안과 페이지에 이 구분과 백업 날짜를 명시했다.

원본 백업·변환 SQL·전체 대화·리뷰 본문·회원·세션·인증 데이터는 게시하지 않는다. 공개 이미지에는 사전 검토한 일반 영화 질문, 응답 발췌, 공개 영화 정보와 집계 결과만 사용한다.

## 핵심 ERD 추가

같은 논리 백업의 DDL에서 핵심 8개 테이블과 실제 선언된 FK 7개를 확인해 ERD로 정리했다. 표시 필드의 존재와 PK, FK 필드의 NOT NULL 여부를 DDL과 대조했다.

- 영화 → 미디어·리뷰·프로필 임베딩·임베딩 작업: 영화 한 건에 하위 레코드 0개 이상. 하위 레코드는 영화 한 건을 필수 참조.
- 사용자 → 대화 세션·리뷰: 사용자 참조 필드가 nullable이므로 사용자 없는 레코드도 허용.
- 대화 세션 → 메시지: 세션 한 건에 메시지 0개 이상. 메시지의 세션 참조는 필수.
- 임베딩 고유키 `(movie_id, document_type, chunk_no, embedding_model)` 및 `vector(1024)` 기반 도메인 확인.
- `chat_messages.sources`는 JSONB이므로 영화 FK 관계를 임의로 추가하지 않음.
- 카테고리·편집·배치 이력·감사·인증 보조 테이블과 개인정보 필드는 가독성을 위해 생략. 전체 DB나 본인 단독 설계 범위라는 표현은 사용하지 않음.

시스템 아키텍처 하단에 ERD를 배치하고 원본 SVG 확대 링크 제공. 린트·빌드 및 정적 출력 내부 참조 검사 통과.

## 표시 문구 및 로그 이미지 정리

사용자 요청에 따라 서비스 페이지와 ERD에서 백업 시점·작성 근거 설명을 제거했다. 시스템 아키텍처의 ‘교육 팀 프로젝트 발표자료’ 캡션도 제거했다. 이 문서의 분석 기록은 내부 검토 이력으로 유지한다.

기존의 DB 예시 이미지 두 개를 실제 실행 로그의 주요 필드 발췌 이미지로 교체했다. 제공된 로그 파일의 원본 행 번호·수집 시각·노드명·경과 시간과 검수·재시도 필드의 값을 그대로 사용했다. 대화·피드백·서버·프로세스 식별정보는 제외하고 표시 형식만 정리했다. 원본 서비스 UI나 원본 파일 전체를 캡처한 것이라고 표현하지 않는다.

- 근거 부족 후 재검색·검수 통과: 원본 92, 98, 104행.
- 의도 불일치 재시도 및 안전 종료: 원본 141, 153, 159, 161행.

중복된 실행 사례 설명을 제거하고 ‘데이터 로그’ 항목에 통합했다.


## 원문 형식으로 교체

추가 요청에 따라 동일한 7개 원본 JSONL 행의 발췌 이미지로 교체했다. JSON 재직렬화 없이 필드 순서와 피드백을 포함한 원문을 유지하고 서버명·로그 경로만 마스킹했다. 화면의 자동 줄바꿈 외에 문장을 재배열하지 않았다. 대응하는 JSONL 발췌 파일도 연결했다.
