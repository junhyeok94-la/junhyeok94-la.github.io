# GS리테일 운영 가이드 검토 기록

검토일: 2026-10-31

## 검토 범위

사용자가 제공한 운영 가이드 PDF 101개, 총 535쪽을 목록화하고 텍스트를 추출했다. 빈 목차·이미지 중심 문서도 포함된 수치이며 모든 페이지의 시각 검토 완료를 의미하지 않는다. 구조·배포·STG 추가·Serverless 적용의 핵심 페이지는 렌더링해 대조했다. 원본과 추출 텍스트·스크린샷은 공개 자산으로 복사하지 않았다.

## 포트폴리오에 반영한 구조

- STG: 원천 RDBMS → 수집 도구·EMR → S3 1차 적재 → dbt Bash 실행 → Redshift STG 2차 적재.
- Mart·BI: Cosmos DbtTaskGroup으로 태그와 모델 의존성을 반영. STG 전체를 Cosmos가 실행한다고 표현하지 않는다.
- Control DAG: 선행 완료 확인, 하위 DAG 호출, 실행 구간 전달. SubDagOperator 사용을 의미하지 않는다.
- 선택적 Serverless: DbtTaskGroup 내 개별 대상의 실행 환경을 바꾸기 위한 공통 함수. 선정 모델을 제외하고 별도 run·test 태스크를 만든 후 선행·후행 의존성을 연결.
- 시간별 누락 복구: 마지막 성공 종료 구간을 Variable에 저장. 다음 시작 구간 및 선행 완료 범위를 기준으로 계산하며 최대 24시간은 복구 소요 시간이 아닌 대상 범위.
- 배포: dev 개발 배포·검증 → 운영 브랜치 병합 → 운영 배포. 사용자가 최신 메시지에서 지정한 운영 브랜치 이름 `prd`를 우선 반영했다.
- 배포와 실행 구분: Bamboo에서 dbt parse로 manifest 생성. 실제 데이터 처리는 Airflow 실행 시 dbt run·test로 수행. dbt와 Airflow 코드를 구분해 배포하는 구조.

## 문서 간 차이와 공개에서 제외한 주장

- 브랜치 가이드에는 현재 상태와 향후 권장 Gitflow가 함께 존재한다. feature/hotfix, 리뷰 승인 인원, 자동 트리거를 실제 도입 완료 실적으로 쓰지 않았다.
- 문서에는 운영 브랜치를 master로 적은 부분과 환경명 표기가 혼재한다. 최신 본인 설명인 prd를 웹에 사용하고, 과거 문서를 임의로 고치지 않았다.
- 아티팩트 분리를 설명하는 문장과 예제 스크립트의 복사 방식만으로 모델 단위 manifest 필터링이나 파싱 10배 개선을 입증할 수 없어 수치 성과로 사용하지 않았다.
- 인프라 설명의 ECS/Fargate 구성과 일부 배포 스크립트의 EC2 전송 설명이 혼재한다. 공개 도식에는 배포 목적지의 상세 호스트·파일 경로·전송 토폴로지를 표시하지 않았다.
- 운영 가이드에 있는 RPU 자동 조정, 보관 주기 관리, 메타 검증, 의존성 추출 도구는 본인의 개별 설계·구현 범위가 확인되기 전 개인 성과로 추가하지 않았다.
- 원본의 내부 시스템·스키마·모델·DAG 이름, 호스트, 계정, DB 연결 설정, 권한 구성과 비공개 화면은 게시하지 않았다.

## 도식 관리

`python scripts/build-gs-diagrams.py`로 플랫폼·배포 도식을 다시 생성한다. 개인 자료를 읽는 스크립트가 아니며 검토된 공개 개념만 포함한다. AWS 아이콘은 공식 Architecture Icons 패키지를 사용하고 출처는 아이콘 폴더 README에 기록했다. 문서용 기존 SVG는 각 viewBox 비율을 그대로 사용한다.

## 전체 시스템 도식 보완

`01-1. 시스템 아키텍처 및 역할 정의` 첫 페이지에 전체 시스템 도식이 존재한다. 최초 웹 수정에서는 STG 경로가 대표 아키텍처로 배치되어 범위가 축소됐다. 전체 구성도에 수집 API/Fargate, EMR, S3, Redshift, 선택적 Serverless 및 Data Sharing, BI/Athena, Aurora·ECR·Lambda 지원 서비스를 반영하고 STG 처리 흐름은 상세 도식으로 이동했다. 원천 시스템·스키마 이름과 물리 망 정보는 제외했다. 원본 AWS 계정·VPC 등의 연결 토폴로지를 재현한 물리 구성도가 아닌 공개용 시스템 역할도다.
