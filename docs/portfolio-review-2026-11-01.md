# 프로젝트 포트폴리오 점검 — 2026-11-01

홈과 프로젝트 상세 7개를 대상으로 문장, 담당 범위, 설명의 구체성, 누락 내용, 이미지와 링크를 점검했다. 현재 내용과 이전에 확인한 수행 경험을 기준으로 수정했으며, 확인되지 않은 기능이나 성과 수치는 추가하지 않았다.

## 공통 수정

- 실무 프로젝트의 문제·실행·결과를 명사형 중심으로 정리. 질문형 소개와 모호한 결과 표현 축소.
- GS리테일의 고부하 모델 사례 제목에서 검증되지 않은 비용 절감 인상을 제거하고 실행 환경 분리로 명시.
- 지방재정 화면 수의 단위를 ‘본’에서 ‘개’로 정리. 유형분류 11개가 심화 화면 30여 개에 포함된다는 범위 유지.
- 한화·UBASE의 단순 기술 관계도 제목을 ‘기술 구성’으로 변경. 실제 운영 아키텍처로 오인할 수 있는 표현 축소.
- UBASE의 확인된 메뉴 개편·이력 관리 내용을 문제·실행·결과로 정리. 아직 구체적인 변경 전후 사례는 부족.
- Pop Talk의 화면을 ‘팀 구현 결과’로 명시하고 개인 담당 업무와 구분.
- Pop Talk 화면 4개의 실제 이미지 크기 반영. 관리자 대시보드(1475×1060)에 잘못 지정됐던 가로형 비율 수정. 홈의 실무 도식도 SVG 원본 비율 사용.

## 빠진 내용과 과장 방지

- 한화는 ‘문제와 해결’ 항목을 채울 수행 사례가 부족하다. 빈 제목을 표시하지 않지만, 내용이 충분하다는 뜻은 아니다.
- LG화학·UBASE는 결과를 입증할 구체적인 선택·변경 사례가 더 필요하다. 개선율·처리량 등 측정하지 않은 수치를 새로 만들 필요는 없다.
- GS리테일의 최대 24시간은 복구 **대상 구간**이며 복구 소요 시간이 아니다. 1,000개 이상 모델의 공통 실행 기준과 전체 모델 단독 개발도 구분한다.
- KICS의 내부 분석 자료는 최종 구축 아키텍처를 증명하는 자료가 아니다. 재구성한 논리도와 확인된 제품 역할 범위로 설명한다.
- 지방재정의 공개 이미지를 개인 개발 화면이나 스마트 빅보드 단독 개발 결과로 표기하지 않는다.
- Pop Talk의 수상과 제품 화면은 팀 결과다. 본인 역할은 데이터·RAG·Agent·인프라 구현 참여 범위로 유지한다.

- `npm run lint`, `npm run build` 통과.
- 정적 출력 8페이지의 내부 참조 157개와 로컬 이미지 25개 점검: 누락 대상·깨진 앵커·이미지 종횡비 불일치 없음.
- 공개 페이지의 TODO·TBD·작성 예정 등 임시 문구 미검출.
- 기사·제품 소개·GitHub·기사 이미지 등 외부 URL 8개 HTTP 200 응답 확인. 응답 상태는 해당 시점의 접근 가능 여부이며, 인용 내용의 추가 사실 검증을 대신하지 않음.
- Pop Talk의 펼친 관리자 화면을 브라우저에서 확인. 원본 비율 유지.

다음 보완 순서는 한화 → LG화학·UBASE → KICS·지방재정·Pop Talk가 적절하다. GS리테일은 새로운 내용을 늘리기보다 기존 사례의 증거를 짧게 보강하는 수준이면 충분하다.
