# 차세대 KICS 데이터플랫폼 포트폴리오 검토

검토일: 2026-10-31

## 근거 구분

1. 최신 사용자 확인: 데이터플랫폼 구축 담당. SBP와 Hadoop Ecosystem 기반 환경에서 데이터스트림즈 TeraStream으로 파이프라인 개발. 법무부를 제외한 검찰청·경찰청·해양경찰청의 대시보드 화면 설계 및 문서 작성. 1차 설계 완료 후 MSTR 개발 담당자가 인계받아 실제 화면 개발.
2. 첨부 현황분석서: 82쪽 스캔본. 모든 페이지를 로컬 렌더링·OCR했고, 목차와 핵심 사업 범위·로드맵 도식을 직접 확인했다. OCR 오인식이 있어 세부 고유명사·숫자를 그대로 사용하지 않았다.
3. 공개 자료: 정부 KICS 개통 자료와 공식 제품 설명·공급사 보도자료로 사업 맥락과 제품 역할을 대조했다. 제품 소개가 KICS의 실제 설치 구성이나 성과를 증명하지는 않는다.

## 현황분석서에서 확인한 내용

- PDF 1~61쪽: 선진사례, 내부 업무·데이터 현황과 시사점 중심. 내부현황은 검찰을 중심으로 설명한다. 해외 사례와 타 기관 벤치마킹을 KICS 구현 성과로 옮기지 않았다.
- PDF 62~67쪽: 회전된 별첨 페이지. 자동 OCR만으로 의미를 확정하지 않았다.
- PDF 68~82쪽: 분석과제 발굴·선정의 연구용역 범위와 진행계획. 특히 71쪽은 데이터플랫폼 사업 아래 데이터플랫폼 구축(데이터레이크·사용자포털·시각화)과 지능형 사건처리지원 서비스를 구분한다.
- PDF 70·72·74쪽: 현황분석, 과제 발굴·정의와 중장기 로드맵 수립 등 컨설팅 단계의 범위. 후보 과제나 예시 화면을 구현 완료된 서비스로 표기하지 않았다.
- PDF 78~80쪽: Illustrative 또는 향후진행으로 표시된 예시. 본인 화면 설계 결과 또는 실제 구현 화면으로 사용하지 않았다.
- PDF 81쪽: 수행 조직에 제3자 인명이 포함된다. 원본 페이지와 인명·연락처를 공개하지 않았다.
- 로컬 OCR 텍스트에서 SBP·Hadoop·Hive·TeraStream 제품명은 식별되지 않았다. 최종 설치 아키텍처를 이 문서로 검증했다고 주장하지 않는다.

## 웹에 반영한 범위

- 전체 데이터플랫폼 사업과 본인이 맡은 구축 영역을 분리.
- TeraStream 수집·변환·적재, SBP/Hadoop·Hive 저장·처리 역할을 공개용 논리도로 재구성. 실제 기관 간 데이터 통합·공유, 단일 클러스터 또는 직접 연계 프로토콜은 표시하지 않았다.
- BLOB 적재 오류 대응, ETL 공통 표준 및 Python 법령정보 API 신규 연계는 기존 본인 확인 사실을 유지.
- 대시보드 화면 설계 대상과 인계 흐름을 별도 도식으로 추가. MSTR 화면 개발과 지능형 사건처리지원 서비스 개발을 개인 성과로 쓰지 않았다.
- 내부 데이터 모델, 상세 분석과제, 실제 기관별 화면 설계서·스크린샷, 접속 정보와 원본 PDF는 공개 파일에 포함하지 않았다.
- Kafka, Spark, HBase, ZooKeeper, 클러스터 버전·대수, 최신 SBP의 Delta Lake·Vector DB 등은 KICS 적용 근거가 없어 추가하지 않았다.
- TeraStream의 에디션이 for Hadoop이었는지는 확인되지 않아 제품명을 TeraStream으로만 기록했다.

## 추후 보완 가능한 자료

실제 설치·운영 구성도나 본인이 작성한 대시보드 설계 문서가 확보되면 공개 가능한 항목만 비식별화하여 구체화할 수 있다. 현재 논리도를 승인된 물리 구성도나 원본 설계 화면으로 표시하지 않는다.
